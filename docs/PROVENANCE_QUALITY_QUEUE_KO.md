# 근거 품질 큐

## 목적

CEO가 모든 근거를 일일이 훑지 않아도 반려되었거나 아직 검증되지 않은 근거를 먼저 확인할 수 있게 합니다. 이 기능은 기존 근거 원장과 검토 이력만 읽으며, AI 호출·외부 조회·데이터 변경을 하지 않습니다.

## API

`GET /api/v1/provenance/quality`

- `limit`: 반환할 큐 항목 수, 기본 100, 최대 200
- `include_verified`: `true`이면 검증 완료 항목도 반환합니다. 기본값은 `false`입니다.
- 요약은 `limit`과 무관하게 현재 테넌트 전체 근거를 기준으로 계산합니다.
- 다른 테넌트의 근거와 검토 이력은 집계하거나 반환하지 않습니다.

응답에는 규칙 버전, 생성 시각, 전체 요약과 우선순위 큐가 포함됩니다. 검증률은 `검증 완료 수 / 전체 근거 수`를 반올림한 정수 백분율입니다. 반려 근거는 검증률에 포함하지 않습니다.

## 규칙 v1

우선순위는 아래 순서입니다.

1. `rejected`: 반려 근거, 긴급
2. `unverified_decision`: 미검증 대표 결정, 긴급
3. `unverified_knowledge`: 미검증 연구 지식, 행동
4. `observed_decision`: 출처만 관찰된 대표 결정, 행동
5. `observed_knowledge`: 출처만 관찰된 연구 지식, 관찰
6. `verified`: 검증 완료, 정상

같은 분류 안에서는 오래된 근거가 먼저 오고 ID로 순서를 안정화합니다. 상속된 근거도 자기 검증 상태로만 분류하며, 원본 근거의 판정을 자동 전파하지 않습니다.

## 안전 경계

- 읽기 전용입니다. 감사 이벤트도 새로 만들지 않습니다.
- URL이 있더라도 네트워크로 원문을 다시 조회하지 않습니다.
- 프롬프트, API 키, 원문 전체를 응답하지 않습니다.
- 자동 검증·자동 반려·자동 업무 실행을 하지 않습니다.
- 분류 규칙이 바뀌면 `rule_version`을 올립니다.

## CEO Desk

근거 원장 상단에 검증률, 검토 대기 수, 반려 수와 최대 8개의 우선 검토 항목을 표시합니다. 실제 검증과 반려는 기존 해시 결합 검토 API를 통해 대표가 수행합니다.
