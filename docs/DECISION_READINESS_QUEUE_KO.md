# 결정 신뢰도 큐

결정 신뢰도 큐는 구조화된 대표 결정의 생명주기와 근거 원장의 검증 상태를 하나의 읽기 전용 운영 화면으로 연결한다. 새 AI 호출, 외부 전송, 결정 상태 변경 없이 저장된 데이터만 규칙으로 계산한다.

## API

`GET /api/v1/decisions/readiness`

쿼리:

- `limit`: 반환 항목 수, 기본 100, 최대 200
- `include_ready`: 준비 완료 결정을 항목에 포함할지 여부, 기본 `false`
- `include_closed`: 종료 결정을 항목에 포함할지 여부, 기본 `false`

요약 수치는 `limit`과 포함 옵션에 관계없이 해당 테넌트의 전체 결정을 기준으로 계산한다. 기본 큐는 대표가 확인해야 할 `blocked`, `review`, `watch`만 반환한다.

## 결정 규칙

규칙 버전은 `decision-readiness-v1`이다. 동일한 데이터와 기준 시각에는 같은 결과가 나온다. 우선순위가 높은 첫 신호가 대표 사유가 되며 모든 해당 신호는 `signals`에 함께 남는다.

1. `closed`: 대체·만료·철회된 종료 결정
2. `blocked`: 활성 결정의 만료일 경과, 반려 근거, 근거 없음
3. `review`: 재검토일 경과, 제안 상태, 미검증 근거
4. `watch`: 관찰 근거, 14일 이내 만료, 14일 이내 재검토
5. `ready`: 연결된 모든 근거가 검증 완료

종료 결정은 신뢰도 판단 대신 `closed`로 분리한다. 반려 근거가 하나라도 있으면 다른 검증 근거가 있어도 `blocked`가 우선한다.

## CEO Desk

회사 맥락 영역의 `DECISION ASSURANCE / 결정 신뢰도` 카드가 준비·검토·차단 수와 우선 확인할 결정 6건을 표시한다. 화면에는 상태 확인 정보만 있으며 결정 확정·철회나 근거 검토 동작을 자동 수행하지 않는다.

## 안전 경계

- API 키 인증과 `X-Tenant-ID` 격리를 그대로 적용한다.
- 조회 중 감사 이벤트나 업무를 생성하지 않는다.
- 데이터베이스 스키마 변경이 없다.
- OpenAI와 외부 네트워크를 호출하지 않는다.
- 이 큐는 운영 판단 보조 정보이며 법률·재무·규제 적합성을 보증하지 않는다.

## 운영 확인

배포 후 `SMOKE_DECISION_READINESS.bat`을 실행한다. Render의 `APP_API_KEY` 값을 클립보드에 복사한 뒤 배치 파일을 실행하면 준비 상태, OpenAPI 계약, 큐 응답, 규칙 버전과 반환 레벨을 읽기 전용으로 확인한다.
