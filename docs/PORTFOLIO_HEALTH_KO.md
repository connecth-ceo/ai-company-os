# 포트폴리오 건강도

## 목적

Goal → Project → Task 계층의 현재 데이터를 읽어 대표가 목표일 위험, 보류 상태, 실패 업무와 전체 진척을
한 화면에서 확인하게 한다. 같은 입력은 항상 같은 결과를 만들며 OpenAI를 호출하지 않는다.

## API

`GET /api/v1/portfolio/health`는 현재 회사 범위의 요약과 목표·프로젝트별 건강도를 반환한다.
목표·프로젝트 상세 목록은 기본 100개이며 `limit`으로 1~200개를 선택할 수 있다. 요약 수치는 목록 제한과
관계없이 회사 전체 데이터를 기준으로 계산한다.

- 규칙 버전: `portfolio-health-v1`
- 건강도: `healthy`, `watch`, `action`, `critical`, `closed`
- 전체 업무 완료율: 완료 업무 수 ÷ 프로젝트에 연결된 전체 업무 수
- 목표 진척률: 목표에 연결된 모든 프로젝트 업무의 완료율
- 프로젝트 진척률: 프로젝트에 직접 연결된 업무의 완료율
- 업무가 없으면 완료율은 0으로 표시한다.

## 결정론적 규칙

위에 있는 규칙이 먼저 적용된다.

### 목표

1. 달성·취소·보관 목표는 `closed`다.
2. 열린 목표가 목표일을 넘기면 `critical`이다.
3. 보류 목표 또는 실패 업무가 있는 목표는 `action`이다.
4. 목표일까지 14일 이내이거나 아직 시작 전이면 `watch`다.
5. 활성 목표에 연결 프로젝트가 없으면 `watch`다.
6. 그 밖에는 `healthy`다.

### 프로젝트

1. 완료·보관 프로젝트는 `closed`다.
2. 보류 프로젝트 또는 실패 업무가 있는 프로젝트는 `action`이다.
3. 계획 상태이거나 활성 상태인데 업무가 없으면 `watch`다.
4. 그 밖에는 `healthy`다.

## CEO Desk

- 포트폴리오 상단에 전체 완료율, 열린 목표, 기한 초과, 마감 임박, 조치 필요 수를 표시한다.
- 목표·프로젝트 카드에 건강도 배지와 완료율 막대를 표시한다.
- 건강도 배지 설명은 목표일 초과, 보류, 실패 업무, 미시작 등 규칙 근거를 보여준다.

## 안전 경계

- 건강도 조회는 상태 전이, 업무 실행, 승인, 재시도 또는 외부 행동을 시작하지 않는다.
- DB 행을 추가·수정·삭제하지 않고 AuditEvent도 만들지 않는다.
- 모든 조회는 `X-Tenant-ID`의 회사 범위 안에서만 수행한다.
- 별도 DB 열이나 테이블을 추가하지 않으므로 Alembic revision은 바뀌지 않는다.
