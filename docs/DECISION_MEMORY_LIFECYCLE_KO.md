# 대표 결정 메모리 수명주기

## 목적

대표의 결정을 단순 메모가 아니라 상태·적용 범위·효력 기간·대체 이력을 가진 회사 기록으로 보존합니다.
AI 업무에는 지금 효력이 있는 결정만 전달되므로, 검토 중이거나 철회·만료·대체된 방침이 새 업무를
오염시키지 않습니다.

## 결정 상태

| 상태 | 의미 | 다음 상태 |
| --- | --- | --- |
| proposed | 검토 중인 제안이며 AI 맥락에 포함되지 않음 | active, revoked |
| active | 확정되어 현재 AI 업무에 반영되는 결정 | expired, revoked, 새 결정으로 대체 |
| superseded | 후속 결정으로 대체된 보존 이력 | 변경 불가 |
| expired | 설정한 만료시각이 지난 뒤 명시적으로 종료한 이력 | 변경 불가 |
| revoked | 대표가 철회한 이력 | 변경 불가 |

이미 종료된 결정을 다시 활성화하지 않습니다. 잘못된 결정을 고치려면 새 결정을 기록하고 이전 결정을
대체하거나 철회합니다. 이 방식은 감사 이력을 지우지 않습니다.

## 적용 범위

| 범위 | applies_to 값 |
| --- | --- |
| company | 빈 객체 |
| project | project_id 하나 |
| task | task_id 하나 |
| department | department 하나 |

Project와 Task 범위는 같은 회사의 실제 레코드인지 검사합니다. 다른 회사의 ID는 존재 여부를 노출하지 않고
찾을 수 없음으로 처리합니다. 대체 결정은 이전 결정과 동일한 범위와 대상을 가져야 합니다.

## 효력 규칙

AI 업무에 전달되는 결정은 아래 조건을 모두 만족해야 합니다.

1. 상태가 active입니다.
2. effective_at이 현재시각과 같거나 이전입니다.
3. expires_at이 없거나 현재시각보다 이후입니다.
4. company 범위이거나, 실행 중인 Task·Project와 적용 대상이 일치합니다.

만료시각이 지난 active 결정은 즉시 AI 맥락에서 제외됩니다. 상태를 expired로 바꾸는 작업은 이력을
명확히 정리하기 위한 별도 전환이며, 현재 단계에는 자동 스케줄러가 없습니다.

현재 일반 Task에는 부서 식별자가 없으므로 department 결정은 저장·조회·검증할 수 있지만 AI 실행 맥락에는
아직 주입되지 않습니다. 후속 Task/Role 부서 식별자 설계에서 연결할 예정입니다.

## CEO Desk 사용법

1. 회사 맥락 영역에서 **대표 결정 기록**을 누릅니다.
2. 바로 적용할 내용은 **확정 결정**, 아직 검토 중이면 **검토 중인 제안**을 선택합니다.
3. 기존 방침을 바꾸는 경우 **기존 결정 대체**에서 이전 결정을 선택합니다.
4. 저장된 제안은 **확정**, 활성 결정은 **철회** 버튼으로 상태를 바꿀 수 있습니다.

대체된 결정은 삭제되지 않고 **대체됨** 상태로 남습니다.

## API

- 생성: POST /api/v1/decisions
- 목록: GET /api/v1/decisions
- 상세: GET /api/v1/decisions/{decision_id}
- 상태 전환: POST /api/v1/decisions/{decision_id}/transition
- 현재 효력 있는 결정만 조회: GET /api/v1/decisions?effective_only=true
- 상태 필터: GET /api/v1/decisions?status=active
- 범위 필터: GET /api/v1/decisions?scope=project

기존 subject, choice, rationale만 보내는 형식은 계속 지원됩니다. 이 경우 active, company, 즉시 효력으로
저장되어 기존 CEO Desk와 V0.4 흐름이 깨지지 않습니다.

## 감사와 안전 경계

- 생성, 활성화, 철회, 만료, 대체를 AuditEvent에 기록합니다.
- 회사별 데이터 격리를 모든 생성·조회·전환에 적용합니다.
- 자기 자신 대체, 한 결정을 두 번 대체, 범위가 다른 대체를 DB와 서비스 양쪽에서 차단합니다.
- 결정 저장과 상태 전환은 OpenAI를 호출하지 않으므로 AI 비용이 없습니다.
- 이 기능은 회사 내부 운영 맥락을 관리합니다. 외부 발송·결제·삭제·배포를 자동 승인하거나 실행하지
  않습니다.

## 배포 후 무비용 점검

Render에서 APP_API_KEY 값을 복사한 뒤 저장소 루트의 SMOKE_DECISION_MEMORY.bat을 더블클릭합니다.
이 검사는 이름이 [SMOKE]로 시작하는 결정 두 건을 만들고 제안 제외, 활성화, 대체, 효력 목록을 확인합니다.
OpenAI 업무는 실행하지 않습니다.
